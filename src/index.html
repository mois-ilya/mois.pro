Developer platforms

At Tonkeeper, I worked on the layer between the public API and the engineers using it: the OpenAPI schema, generated TypeScript SDK, developer console and integration guides. Some of that work also reached the wallet and the TON Connect specification.

For 21 months I was the only developer on the console. I moved its billing from TON to USDT without forcing existing subscribers through a hard cutover, and built webhooks management, pricing tiers, analytics queries and airdrop tooling.

From mid-2024 I also maintained tonapi-js, the TonAPI TypeScript SDK, on my own. I rewrote its packages and generator so the public schema produced an isomorphic client with int64 values preserved as bigint and one runtime dependency.

Two ambiguities I found in TON Connect became edits to the TON Connect protocol specification: the address format in a sign-data response and the encoding of appDomain. In both cases, the old wording allowed two conforming implementations to produce different messages for the same request.

Building now

Since March 2026 I have been building two private products.

The first splits shared expenses. An edit appends an event instead of overwriting the bill, so concurrent changes survive and every balance can be rebuilt from history. Property-based tests compare the settlement algorithm with a smaller reference implementation.

The second turns a receipt photo into line items that several people can claim at the same time. It runs on Cloudflare Workers with no origin server. A staged extraction pipeline can switch vendors at each step, and its arithmetic must match the receipt total before the result is shown.

The public repositories and both private products are collected on the projects page.
