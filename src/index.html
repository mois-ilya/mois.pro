About

I've been a software engineer for eight years. The last two went into Tonkeeper's developer platform: the console, the TonAPI SDKs, and two passages of the TON Connect spec that were vague enough for independent implementations to disagree.

Work aimed at other developers has one property I like — when something is wrong, someone tells you within a day, usually with a reproduction attached.

Up close the work is less tidy than a list of it looks. The SDK is generated from an OpenAPI schema, and to make the generator emit what the schema actually meant I had to write custom templates — which crashed, because one of the helpers the generator hands to a template arrives without its this. The fix is a single line. It lives in patches/ as a diff against someone else's package, and the generator version is pinned exactly so the diff keeps applying.

Before Tonkeeper: a booking platform, an Amazon Seller Central ingestion pipeline, a backend moved off a VPS onto AWS, and a stretch leading three to five engineers through about eleven releases.

Now

Two products, both mine, both still private.

One splits expenses. Nothing in it is ever overwritten: every edit is appended as an event, so when two people edit the same bill at once both edits survive, and balances are derived rather than patched.

The other turns a photo of a receipt into line items everyone at the table claims at once. It started on a server I ran myself. At the traffic it actually had, that server cost more than it was worth and took longer to deploy to than the changes took to write, so I moved the whole thing onto Cloudflare Workers. There is no origin server now — that was a correction, not the original plan.

Selected work

  • tonapi-js — the TypeScript SDK for TonAPI, ~14k installs a week. I've maintained it on my own since mid-2024, and rewrote the packages and the generator behind them.
  • ton-console — Tonkeeper's developer console: billing, webhooks, pricing tiers, the analytics query builder. I was the only developer on it for 21 months, and moved billing from TON to USDT without a hard cutover for users already paying in TON.
  • TON Connect specification — two of my edits are in the protocol: the address format in a sign-data response, and appDomain encoding.
  • ton-sign-data-reference — a TypeScript reference implementation of TON Connect SignData.

Everything else I'm building is on the projects page.
